## Object Part Confusion (1 cases, 5.0%)

### Example: user_031 (package)

| Field | Expected | Predicted |
|-------|----------|-----------|
| claim_status | `supported` | `not_enough_information` |
| issue_type | `water_damage` | `water_damage` |
| object_part | `package_side` | `unknown` |

**GT justification:** The image supports the water damage claim, but user history shows prior package claims often needed evidence review.

**Model justification:** No valid images were available for assessment. Missing: Readable image showing package unknown with visible water damage damage.

**Root cause:** The claimed part 'package_side' was not identified; model predicted 'unknown'. Possible reasons: (1) image focuses on a different part than claimed, (2) claim extraction mapped the wrong part from the conversation, (3) VLM confused adjacent parts (e.g. bumper vs fender).

**Actionable recommendations:**

- Improve part-matching in vision_agent._aggregate(): track per-image object_present votes separately.
- Tune VISION_EVIDENCE_USER to include labeled examples of each object_part.
- Re-examine ClaimExtractionAgent: ensure claimed_part maps to the taxonomy correctly.
- Filter supporting images: only include images where supports_claim=True AND no WRONG_OBJECT flag.
